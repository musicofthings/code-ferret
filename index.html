CodeFerret is an autonomous code-review and bug-hunting plugin — for Claude Code, and via MCP for Claude Desktop, OpenAI Codex, Gemini CLI, and any other MCP client. It reviews the changes you actually made — not your whole repo — and only reports issues it can back with a concrete failure scenario.

/code-ferret:review

Deep, diff-scoped semantic review

Point CodeFerret at your changes and it reads them like a detective — tracing suspicious lines across five detection vectors and reporting only what it can prove.

  • Clickable file:line:col locations, with severity and confidence per finding
  • Ready-to-apply patches, each checked with git apply --check
  • Findings saved to .ferret/last-review.json
# uncommitted changes vs HEAD
/code-ferret:review
/code-ferret:review staged   # staged only
/code-ferret:review main     # branch vs main

Five detection vectors, zero style nitpicks

CodeFerret targets deep semantic flaws that compilers and linters miss. Anything a linter already enforces is deduplicated away.

LOGIC

Run-time integrity

Off-by-one errors, boundary conditions, null/undefined flow, unhandled promises, resource leaks, infinite loops.

SECURITY

Vulnerability trapping

Hardcoded secrets, SQL injection, XSS, unsafe deserialization, OWASP Top 10 patterns.

CONCURRENCY

Asynchronous safety

Race conditions, deadlocks, non-atomic read-modify-write, unsynchronized shared state.

PERFORMANCE

Resource conservation

O(N²) loops over unbounded data, N+1 query patterns, redundant allocations.

API

Contract enforcement

Breaking public API changes, type-safety violations, third-party SDK misuse.

NOISE CONTROL

False-positive cache

Dismiss a finding once and its structural pattern is suppressed in every future review. Commit the cache to share it with your team.

/code-ferret:triage

Walk your findings, one at a time

Triage steps through each finding and hands you the decision — nothing gets applied behind your back.

  • Accept & apply patch — applies the fix and confirms it compiles
  • Ignore pattern — suppresses that structural pattern forever
  • Discuss or Skip — keep control of every call
/code-ferret:precommit

A fast gate before every commit

A staged-only check for commit blockers — secrets and high-confidence critical bugs — with a single-line verdict.

  • Returns one clear FERRET: PASS or FERRET: BLOCK
  • Built-in guard scans staged changes for GitHub, AWS, Anthropic & Slack tokens and private keys
  • Pure pattern match on git commit — no LLM call, no latency

v0.3.2

Same review, a twelfth of the tokens

A five-vector fan-out used to collect the same diff six times — once for the orchestrator and once inside every vector agent. It now collects once and shards the work. Measured on a 33-file diff.

12×fewer tokens per review~480k → ~40k
231×smaller orchestrator output250 KB → 1 KB
3.7×lighter slowest agentsize-balanced shards
100%enclosing-function contextup from 17.8%
12/12planted bugs found by the fan-outup from 6/12
  • ✓
    Complete functions, not fixed windowsHunks now arrive with their entire enclosing function via git -W. The old fixed -U50 window showed just 17.8% of a 617-line function — too little to trace a failure through it. A correctness fix that no token metric would have caught.
  • ✓
    Collect once, then shardAgents share one collected context file and a balanced slice of the diff instead of each re-collecting the whole thing. plan-shards.sh packs by diff size, cutting the fattest shard from 148 KB to 39 KB. Verified live: a logging shim recorded zero collector re-runs across ten agent dispatches.
  • ✓
    Shards split by file, not by vectorEvery agent applies all five vectors to its own files. Splitting per vector covers only a fifth of the file×vector matrix — on a 23-file diff with 12 planted bugs it recalled 6/12, versus 12/12 for file shards, at the same token cost.
  • ✓
    Lockfiles by name, not by bodyTwelve lockfile formats keep their entry in the changed-file and dependency lists, but their thousands of generated lines stay out of the diff. Version-bump analysis is unaffected.
  • ✓
    Pre-commit is finally light/code-ferret:precommit advertised speed over depth but collected at full depth with complete file history. It now runs one light inline pass and never fans out.
  • ✓
    Verified, not assumed12 new shell assertions plus a 144-check coverage eval across 5 repositories confirm no changed file is lost between git, the shard plan, and the collected context.
agents/ferret-reviewer

A dedicated reviewer sub-agent

A large diff is split into balanced file shards and reviewed in parallel by ferret-reviewer agents. Each agent applies all five vectors to its own files, so every changed line is checked against every vector — never a fifth of the matrix.

  • Security, correctness, concurrency and performance evaluated together
  • Findings consolidated into one structured report
  • Deterministic output schema for downstream tooling
Commit guard

Secrets never reach the remote

Once installed, a hook scans staged changes for credentials whenever Claude Code runs git commit — and blocks the commit if any turn up.

$ git commit -m "add config"
CodeFerret blocked this commit: credentials in staged changes.
SECRET src/config.py:1
  • Catches hard-coded keys before they're pushed — no LLM call
  • Add a .ferretignore (gitignore syntax) to exclude generated files
Your machine, your code

Runs entirely on your laptop

No service, no account, no API key. The review is performed by a coding agent you already have installed, so your code never leaves your computer — that is the deliberate difference from hosted reviewers.

  • Standalone CLI — ferret review in any terminal, delegating to your installed claude, codex, or gemini
  • Native git hook — install examples/git-pre-commit-hook for a pure-bash secret guard in plain git
  • No API key, ever — CodeFerret has no service and no account; there is nothing to sign up for and nothing to pay for
Install

Up and running in under a minute

In Claude Code, run these inside any session. Also available for Claude Desktop (one-click .mcpb bundle), OpenAI Codex, Gemini CLI (gemini extensions install), and any other MCP client — see the install guides.

  1. Add the marketplace

    /plugin marketplace add musicofthings/code-ferret

  2. Install the plugin

    /plugin install code-ferret@code-ferret-marketplace

  3. Review your changes

    /code-ferret:review
